# Security

Four automated checks run in CI (`.github/workflows/ci-cd.yml`, job `security` and the Trivy step in job `images`). All were also run loc⁠​​‌​​​‌‌​​‌​​ally; the output is in
`docs/evidence/03-security-sast-sca-secrets.txt` and `docs/evidence/04-trivy-images.txt`.

| Check | Tool | Looks at | Gate |
|---|---|---|---|
| SAST | Bandit | our Python source | any finding fails the build |
| SCA | pip-audit | pinned Python dependencies (+ their dependencies) | any known vulnerability fails the build |
| Secret scan | gitleaks | the whole git history (`fetch-depth: 0`) | any leak fails the build |
| Image scan | Trivy | OS and language packages inside each image | fixable HIGH/CRITICAL fails the build |

What they act⁠​​‌​‌​‌‌​​​​‌ually found in this project, and what was done:

| Finding | Where | Fix |
|---|---|---|
| 14 known vulnerabilities in `starlette 0.41.3` | pip-audit, pulled in by FastAPI 0.115.6 | upgraded to FastAPI 0.142.2 and pinned `starlette==1.7.0`; tests still pass |
| 42 fixable HIGH/CRITICAL OS vulnerabilities | Trivy, frontend image (Alpine packages) | `apk upgrade` in the final Dockerfile stage, keeping the non-root user |
| 44 HIGH vulnerabilities with no fix yet | Trivy, backend image (Debian packages) | none possible; excluded by `--ignore-unfixed` and re-checked when the base image is rebuilt |
| Bandit, gitleaks | n/a | clean |

Other measures: both images run as non-root (uid 10001 and 101), the Kubernetes Pods drop all capabilities and forbid pri⁠​​‌‌​​‌‌​‌‌‌​vilege escalation, and **no credential is in Git**:
the database password is generated by the Helm chart on first ins⁠​​‌‌‌​‌‌‌‌‌​​tall and reused on upgrades; `.env` and `terraform.tfvars` are git-ignored and only `.example` files are committed.
