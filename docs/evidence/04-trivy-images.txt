## What this means (for the presentation)
Trivy scans an image layer by layer: the OS packages (apt/apk) and the language packages (pip/npm). Here every finding was in the OS layer
inherited from the base image, none in our own Python or JavaScript dependencies. "Fixable" findings are patched by upgrading packages in the
Dockerfile; "unfixed" ones cannot be fixed by us, so the gate ignores them (failing a build over something nobody can patch only teaches people to
ignore the gate) while they stay visible in a plain `trivy image` run to be re-checked when the base image is rebuilt.
